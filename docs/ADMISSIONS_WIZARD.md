# Admission wizard — Suffah High School

## Admission wizard with private Cloudflare R2 uploads

The Admissions screen has seven horizontally swipeable tabs. A fixed top bar displays the read-only registration number and roll number, and a fixed footer has Save draft, Back, and Save & next / Complete.

1. **Student** — first/middle/last, DOB, gender, nationality, ID type and number.
2. **Contact** — student email, phone, WhatsApp, street, neighborhood, city, postal code, country and optional emergency contact.
3. **Guardian** — first/middle/last, relationship, primary phone, WhatsApp, emergency contact, email, ID and occupation.
4. **Academic** — read-only registration and roll number, grade/section, campus, academic year, term, editable admission date, previous school/grade and transcript notes.
5. **Health** — optional medical conditions, allergies, blood group and learning accommodations.
6. **Documents** — private student photo, birth/transfer/previous-school certificates and optional medical/other files.
7. **Review** — read-only summary and explicit admission confirmation.

The tab headers scroll horizontally on mobile; users can swipe horizontally between screens. Each tab scrolls vertically on its own. Entered field values remain in memory while navigating.

## Server-reserved identifiers

At the beginning of a *new* admission, a Firestore transaction reads/writes:

- \`counters/student_registration_2026\`, field \`last\` — first record reserves \`ST-2026-0001\`, next \`ST-2026-0002\`. Year changes create a new registration counter.
- \`counters/student_roll_global\`, field \`last\` — initialized from 9999 so the first assigned roll number is \`10000\`, the second \`10001\`. Five-digit range 10000–99999.
- \`students/{registrationNo}\` — created in the same transaction with \`status="draft"\`.

**Numbers are not editable and are never reused.** Closing an unused draft leaves a reserved number rather than creating collisions. If importing existing school records with ST numbers or roll numbers, initialize or migrate the counters first to avoid duplicates. Do not manually reset the counters.

## Save and resume

- A new draft is created in Firestore before opening the form (requires an internet connection).
- Edits autosave after a short pause. Save & next saves the current draft and moves forward. Save draft saves and returns to Students.
- A partially entered record stays in \`students\` with \`status="draft"\`. Tap the draft in Students to resume the last step.
- Complete admission validates student names, date of birth, guardian name/phone, campus and class. It changes status to \`admitted\`.
- Pre-existing v0.2 student documents remain editable through a compatibility reader. Their old registration/roll numbers are preserved.
- The list shows draft and admitted records. **Dashboard counts currently include drafts**, so distinguish enrolled student counts before using totals for official reporting.
- Leaving during a failed cloud save should display an error and keep the wizard open. Internet is required to reserve or sync a draft.

## Firestore structure

\`students/ST-2026-0001\` has canonical \`admissionNo\`, \`rollNo\`, \`status\`, \`currentStep\`, \`active\`, \`createdAt\`, \`updatedAt\`, \`admittedAt\` (when completed) and nested \`details\` maps named \`student\`, \`contact\`, \`guardian\`, \`academic\`, \`health\`.

For list compatibility it retains denormalized \`fullName\`, \`searchName\`, \`guardianName\`, \`guardianPhone\`, \`classId\`, \`gender\`, \`parentUids\`. These are generated by the repository, not manually entered in duplicate.

Student photo storage keys and document metadata remain in the existing photoPath and attachments fields. The Student tab now offers a visible photo uploader; the Documents tab offers photo, certificate/document upload and removal controls. Review also displays uploaded files.

## Cloudflare R2 uploads (Firebase Blaze not required)

Student photos and certificates use a private Cloudflare R2 bucket with a Firebase-authorized Cloudflare Worker. Deployment steps are in docs/CLOUDFLARE_R2.md.

- Photo: JPEG/PNG/etc. compressed to WebP, maximum 100 KiB, uploaded on the Student tab.
- Documents: PDF/JPEG/PNG/WebP up to 5 MiB, uploaded on the Documents tab in categorized slots.
- Owner/principal can add, replace or remove files while editing an admitted student.
- Private profile photo and image documents can be previewed in-app; PDFs can be explicitly saved to a selected device location.
- The Worker URL is injected at APK build time via R2_WORKER_URL; uploads stay disabled with an explanatory message when not configured.
- Firestore student rules remain the final authorization gate for R2 reads and writes; never enable a public bucket URL.
- Previously uploaded Firebase Storage files require an authorized migration.

## Device acceptance checklist

1. Install the successful APK and sign in as the existing owner.
2. Create a class (for example Grade 1 – A).
3. Tap Students → Add student and verify a **read-only** \`ST-2026-XXXX\` registration number and five-digit roll number.
4. Enter a few fields → Save draft → reopen it and confirm the data and last tab are preserved.
5. Swipe between Student, Contact, Guardian, Academic, Health, Documents and Review. Verify tabs and text fields stay usable with the Android keyboard open.
6. Complete the required fields, review the details, and tap **Review & admit → Apply admission**. Verify the student appears as a read-only profile and only owner/principal can edit it.
7. Test a second admission and confirm registration/roll numbers are unique and consecutive (unused draft numbers remain reserved).
8. Deploy the Cloudflare Worker and set the R2_WORKER_URL repository variable, then upload and replace a test photo and certificate and verify both in the saved profile.
9. Verify Android upgrades install in place with the persistent signing identity.
10. Test narrow Android and landscape/tablet display; desktop/iOS remain separate build validation milestones.
