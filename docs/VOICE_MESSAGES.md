# Voice messages and delivery receipts

Deploy the current Firestore rules, then run Deploy Android message notifications in deploy mode. The notification Worker also binds the existing private suffah-school-files R2 bucket as VOICE_FILES. Only the voice-messages/ prefix is used. Update both desktop and mobile clients. Existing text-only clients continue to work.

Owner: School messages > Voice retention (auto-delete icon). Settings apply to new recordings: after recipient playback (unplayed recordings expire in 14 days), 7 days, or 14 days after upload. Voice files are immediately inaccessible once expired; cron removes the R2 object and matching Firestore message/alert/job, up to five per minute. Failed uploads are tracked for cleanup. Existing exports, downloaded copies, screenshots, temporary client files after crashes, and provider backups cannot be remotely erased. Hide-for-me entries may persist as ID-only metadata. No voice file is included in Firestore data exports. Retention changes do not retroactively alter existing recordings.

Receipt semantics: clock = pending local write; one tick = committed; two gray = recipient app acknowledged via alert or conversation; blue = recipient viewed the visible message or finished voice playback. This is not FCM acceptance or OS-level delivery. School-side delivery/read means any authorized administrator on the receiving side. Older messages with no acknowledgments are not assumed read. Voice after-play deletion can remove the bubble before the sender sees blue ticks. No audio is recorded in the background intentionally. Android and Windows microphone/codec behavior must be tested on actual devices.

## Inline recording and conversation deletion
The composer shows only the mic when the input is empty, and only Send when it contains text. Hold to record, slide left to cancel, slide up to lock, release to send. A quick tap also locks recording for desktop accessibility. Locked recordings show delete and send controls. The maximum new recording duration is four minutes; Firestore validates the new metadata limit. At four minutes recording stops and sends automatically. Leaving the app cancels recording.

Owner: Messages > Delete all conversations, or conversation menu > Delete conversation for everyone. A confirmation queues one durable request in chat_cleanup/current. The cron Worker removes the matching thread documents, messages, attachments, scheduled messages, hidden metadata, alert records, voice jobs and private R2 voice prefix. Global deletion sweeps all existing threads and orphan voice/alert records. New writes in affected threads are blocked during deletion; other conversations may have delayed fallback notifications until cleanup finishes. Larger deletions require multiple cron invocations. Active users still appear as contacts for starting a fresh chat. No school accounts or other school records are deleted. Previously downloaded copies and external backups cannot be remotely erased. Deploy the rules and Worker before using the deletion feature. No actual deletion is initiated by installing this update.
