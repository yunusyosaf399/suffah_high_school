# School office voice calls — version 2
Parents/teachers can call the office; owner and authorized principals can call the participant from the conversation header or a call-history bubble. Both sides must update together because v2 uses a different signaling collection. Older call endpoints remain for compatibility with old clients, but old and new call receivers cannot answer one another.

The call screen shows the profile photo, ringing, accept/decline, mute, speaker (Android), and hangup. Call records appear in the existing conversation, with completed duration, missed or declined outcome. No live audio recording. Server finalization removes SDP and retains a short terminal marker; cron finalizes unanswered calls even if the caller closes the app. Owner conversation cleanup also deletes v2 call sessions and call history. Ringtones are per account/device: Android system ringtone picker and notification channel; Windows local audio file or default tone. Android active call service has a persistent notification and microphone foreground service; the app may continue a connected call while minimized if Android allows it. Background incoming calls use the selected notification channel sound, and tapping opens the ringing call screen. No native lock-screen full-screen call UI, no guarantee of delivery if force-stopped, no guarantee of continuous ringing in background. Windows can receive while running/minimized; cannot receive when exited. Ringtone settings and audio files are local to the device.

Deploy updated Firestore rules, Worker, and both clients. Existing TURN credentials are reused; no new secrets or Blaze required. Test phone/desktop calls in each direction, decline, missed call, sound selection, minimize during live audio, and notification tap while app is backgrounded. Confirm ongoing-call notification appears on Android. Actual cross-network performance and Android background behavior require device testing.

## Windows stability and troubleshooting
Native Windows ringtone playback now uses WinMM (WAV via PlaySound; other audio via installed MCI codecs, with fallback to the default WAV). The ringtone does not create a Flutter audioplayers instance on Windows. WebRTC setup, mute and teardown are serialized, and teardown is idempotent. Stage logs contain no SDP, tokens, audio, or user IDs. A dedicated Windows CI build compiles the native runner and release bundle. It does not replace a microphone/device test.

If flutter run prints Lost connection to device, check whether the process actually exited. Capture a fresh run with PowerShell Tee-Object. After a crash, inspect the Windows Application log for application error event 1000 or Windows Error Reporting event 1001 mentioning suffah_high_school.exe. Share only the faulting module, exception code and the last Office call stage (not tokens or private user data). A release build can help distinguish a debugger-only problem, but is not proof that a native crash is fixed. Check Windows microphone privacy permissions before testing. Update both devices to the latest compatible v2 client.
